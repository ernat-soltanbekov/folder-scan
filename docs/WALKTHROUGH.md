# Как устроен folder-scan

Представьте журнал склада: каждое имя — отдельная карточка, права — правила
доступа, mtime — дата изменения. Чтобы перечислить карточки, читать содержимое
самих файлов не требуется.

## 1. От аргументов к настройкам

`main.go` получает аргументы и передаёт их `listing.Parse`. Парсер идёт слева
направо, разбирает объединённые флаги и сохраняет пути без очистки. Это существенно:
`link` и `link/` могут означать разные операции, а `-` — допустимое имя.

Попробуйте предсказать настройки `-l -1 -t -S -- -l`. Последний `-l` здесь уже
имя файла, а не флаг. Сверьтесь с `options.go` и тестом парсера.

## 2. Информация о файле

`os.Lstat` описывает саму символическую ссылку, `os.Stat` — её цель. Когда нужно
показать стрелку, `os.Readlink` возвращает текст пути назначения. Эти функции
не читают содержимое обычного файла.

`FileInfo` содержит переносимые поля. В `syscall.Stat_t` доступны дополнительные
Unix-поля: inode, устройство, UID/GID, число ссылок и выделенные блоки.
Linux и macOS имеют разные типы и представление некоторых полей; поэтому они
вынесены в `platform_linux.go` и `platform_darwin.go`.

## 3. Почему ls -l требует двух проходов

Перед печатью надо узнать самую широкую колонку размера, владельца и количества
ссылок. Сначала измеряются поля всех записей текущего списка, затем печатаются
выровненные строки. При обычном одноколоночном выводе этот проход не нужен.

`total` — выделенные файловой системой блоки, а не сумма логических размеров.
У разреженного файла большой размер может сочетаться с малым количеством блоков.
Устройство имеет специальное значение вместо размера; его формат зависит от ОС.

## 4. Обход дерева и циклы

Вместо вызова функции самой себя используется список ожидающих каталогов.
После чтения каталог закрывается. Дочерние задачи добавляются в обратном порядке,
чтобы при извлечении с конца получить нужную сортировку.

При следовании ссылкам возможен цикл: `child/back -> ..`. Для каждого текущего
пути хранится цепочка `(device, inode)` предков. Совпадение означает цикл.
Общий глобальный список «уже видели» здесь был бы ошибкой: он скрыл бы отдельный
аргумент-ссылку на уже показанный каталог.

`f.Stat` проверяет идентичность открытого каталога. `O_DIRECTORY` отвергает
обычный файл или FIFO, если другой процесс подменил каталог между проверками.

## 5. Возраст: границы важнее названий

Для положительного интервала деление на 24 часа отбрасывает неполные сутки.
Проверки идут по возрастанию: меньше 7, меньше 31, меньше 366, всё остальное.
Отдельный helper отвечает за одну дату; функция для среза только увеличивает
счётчики. `Format` задаёт постоянный порядок категорий независимо от порядка map.

Предскажите категории для 6 суток 23:59:59, ровно 7 суток, 30 суток 23:59:59,
ровно 31 суток, 365 суток 23:59:59 и ровно 366 суток. Затем найдите соответствующие
случаи в `TestWholeDayBoundaries`.

## 6. Как проверять изменения

Сначала выберите наблюдаемое поведение: новый флаг, изменение группировки или
случай с ссылкой. Добавьте маленький пример и ожидаемый результат. Затем запускайте
unit-тест, сквозное сравнение и нужный стресс-тест.

Полезный эксперимент: создайте 100 файлов с одинаковым mtime и различными именами.
Объясните порядок для `-t` и для `-tr`. После этого проверьте своё объяснение
на двух реализациях. Дисциплина повторения превращает код в понятный рабочий навык.
