# folder-scan

[![Audit](https://github.com/ernat-soltanbekov/folder-scan/actions/workflows/ci.yml/badge.svg)](https://github.com/ernat-soltanbekov/folder-scan/actions/workflows/ci.yml)

**Порядок в файлах. Точность в деталях. Проверка под нагрузкой.**

Учебная реализация `ls` на Go для Linux и macOS. Показывает файлы, права, владельцев,
ссылки и даты; после каждого каталога добавляет профиль возраста его записей.
Метаданные читаются напрямую: программа не запускает системные команды и не
читает содержимое файлов. Сеть и внешние Go-модули не нужны.

Автор — **Yernat «GhostOfAstana» Soltanbekov**, студент Tomorrow School с техническим
образованием и военным прошлым. Ежеутренняя практика боевых искусств с 2008 года
отражается в инженерном подходе: дисциплина, повторяемые проверки и устойчивость
к сбоям. Профессиональная цель — работа в команде Astana Hub МИИЦР РК.

## Сборка и запуск

Нужен **Go 1.25+**. Make и Python 3.9+ нужны для полного сквозного аудита.

```sh
git clone https://github.com/ernat-soltanbekov/folder-scan.git
cd folder-scan
go build -o folder-scan .

./folder-scan
./folder-scan -l /usr/bin
./folder-scan -la /dev
./folder-scan -l -t .
./folder-scan -alRrt .
./folder-scan --color=always -F .
```

Без путей используется текущий каталог. Аргумент `-` обозначает каталог или файл
с таким именем. `--` завершает разбор флагов:

```sh
mkdir -- -
./folder-scan -
./folder-scan -- -имя-файла
```

В репозитории есть `main.go`, `go.mod`, отдельный `internal/ageprofile/` и тесты.
`go.sum` не нужен, поскольку внешних зависимостей нет. Бинарник собирается локально
и исключён из Git; все исходники, проверки и документация опубликованы.

## Флаги

| Флаг | Действие |
| --- | --- |
| `-l` | Подробная таблица в нативном формате платформы |
| `-a` | Скрытые имена, `.` и `..` |
| `-r` | Обратный порядок, включая порядок при равных датах |
| `-t` | Сначала недавно изменённые записи |
| `-R` | Рекурсивный обход и профиль возраста каждого каталога |
| `-A` | Скрытые имена без `.` и `..` |
| `-S` | Сначала самые большие записи |
| `-d` | Показать сам каталог, не перечисляя его содержимое |
| `-n` | Подробная таблица с числовыми UID/GID |
| `-i` | Добавить номер inode |
| `-F` | Суффиксы типов: `/`, `@`, `*`, `|`, `=` |
| `-p` | `/` после каталогов |
| `-1` | Одно имя на строку; macOS отменяет `-l`, Linux сохраняет приоритет `-l` |
| `-k` | Итоги в блоках по 1024 байта |
| `-L` | Следовать всем символическим ссылкам |
| `-H` | Следовать ссылкам, переданным аргументами |
| `-P` | Не следовать ссылкам; BSD-совместимое расширение также доступно в Linux |
| `-G` | macOS: автоматические цвета; Linux: скрыть группу в подробной таблице |
| `--color=always` | Цвета даже при перенаправлении вывода |
| `--color=auto` | Цвета для терминального вывода |
| `--color=never` | Без цветов; значение по умолчанию |
| `--no-profile` | Убрать добавленную строку возраста для прямого сравнения с `ls` |
| `--help`, `--version` | Справка и версия |

Короткие флаги объединяются: `-lar` и `-l -a -r` эквивалентны. Для `-t`/`-S`,
`-H`/`-L`/`-P` действует последний соответствующий флаг. Сочетание `-l`/`-1`
повторяет поведение платформы: в macOS действует последний, в Linux — `-l`.
Неизвестные параметры дают сообщение в stderr и ненулевой код завершения.

## Профиль возраста

```text
Age profile: fresh 3 | recent 5 | aging 12 | archived 2
```

| Полные сутки после изменения | Категория |
| --- | --- |
| 0–6 | `fresh` |
| 7–30 | `recent` |
| 31–365 | `aging` |
| 366 и больше | `archived` |

Сутки — ровно **24 часа**, а не смена календарной даты. Поэтому 6 суток и 23 часа
ещё относятся к `fresh`, ровно 7 суток — к `recent`. Будущие даты считаются `fresh`.
Пороги 7, 31 и 366 проверяются с точностью до наносекунды.

Один снимок текущего времени используется для всего запуска. Считаются **видимые
записи всех типов**: обычные файлы, подкаталоги, ссылки и специальные файлы.
Скрытые записи учитываются при `-a`/`-A`; служебные `.` и `..` не учитываются никогда.
По умолчанию используется время самой ссылки, при `-L` — её цели.

Нулевые категории не выводятся. Для пустого каталога, отдельного файла и `-d`
профиля нет. При `-R` каждый профиль относится только к непосредственным записям
соответствующего каталога: вложенные записи не суммируются повторно у родителей.

Это **классификация по правилам** из ТЗ. Модель, API-ключ и обучение не используются.
Публичные функции пакета: `Label(time.Time)`, `Classify([]time.Time)`, а также
`LabelAt`, `ClassifyAt` для проверок с фиксированным временем и `Format` для вывода.

## Совместимость с системным ls

Для воспроизводимого сравнения используется локаль `C` или `C.UTF-8`, стандартный
формат дат и стандартный размер блоков. Вывод имён всегда одноколоночный; ТЗ
разрешает свободный выбор формата за пределами `-l`.

```sh
LC_ALL=C ls -l /usr/bin > /tmp/system-listing.txt
LC_ALL=C ./folder-scan --no-profile -l /usr/bin > /tmp/project-listing.txt
diff -u /tmp/system-listing.txt /tmp/project-listing.txt
```

В подробной таблице учтены разрешения и специальные биты, число жёстких ссылок,
имена владельца и группы, реальные выделенные блоки, размер, дата и `->` для
символических ссылок. Linux и macOS имеют отдельные реализации платформенных
полей, интервала недавней даты, номеров устройств и отступов.

Ссылка на каталог без `-l` обычно раскрывается, как у `ls`. `-l link` показывает
саму ссылку, `-l link/` — каталог назначения. Завершающий `/` у ссылки на обычный
файл даёт ошибку; путь намеренно не очищается функцией, которая потеряла бы `/`.

Ограничения совместимости указаны явно:

- Локализованная сортировка и названия месяцев вне C/POSIX не реализованы.
- Специальные настройки окружения `TIME_STYLE`, `BLOCK_SIZE`, `BLOCKSIZE`,
  `LSCOLORS`/`LS_COLORS` не переопределяют встроенный формат; доступны `-k` и `--color`.
- В macOS определяется маркер расширенных атрибутов `@`, но не маркер ACL `+`:
  разрешённые ТЗ высокоуровневые API Go его не предоставляют. `unsafe`, cgo и
  дополнительные зависимости не добавляются. Аудит отдельно разрешает игнорировать
  ACL-маркер в `/dev`; остальные поля сравниваются.
- `/dev` и изменяемые каталоги не являются атомарными снимками. Некоторые номера
  устройств macOS меняются даже между двумя вызовами системного `ls`.

## Устойчивость и производительность

Обход использует явный список задач; глубина дерева не расходует стек вызовов.
Каталог закрывается до перехода к дочерним каталогам. Его устройство и inode
берутся из открытого дескриптора, а не из предварительного снимка пути. При `-L`
проверяется цепочка предков: цикл останавливается с ошибкой, независимые ссылки
на один каталог не теряются.

`O_DIRECTORY` и неблокирующее открытие защищают от подмены каталога FIFO.
Специальные файлы не открываются для чтения данных. Ошибка одного пути не мешает
вывести остальные. Исчезновение записи, отказ в доступе и повреждённая ссылка
при разыменовании дают диагностику и ненулевой статус. Ошибки и короткие записи
в stdout обрабатываются; бесконечного цикла при записи нулевой длины нет.

Сортировка — собственный стабильный merge sort за O(n log n). Вывод буферизуется
порциями по 64 KiB; поиск имён UID/GID кэшируется на время запуска.

Контрольный запуск на macOS arm64, Go 1.27.1 (2026-10-01):

- Дерево из 100 каталогов и 10 000 файлов: примерно **0,024–0,037 с**.
- `-R ~` по фактическому домашнему каталогу: **0,723–0,981 с**, три запуска,
  без ошибок. Порог ТЗ 1,5 секунды на этой машине выполнен.

Это измерения конкретной файловой системы, не обещание одинакового времени
для дисков любой скорости или каталогов произвольного размера.

## Проверки

```sh
make test         # unit-тесты
make audit        # сравнение с native ls, включая /usr/bin и /dev
make stress       # 10 000 файлов; три замера, порог <1,5 с
make race         # детектор гонок
make imports      # проверка разрешённого списка импортов
make fmt-check vet
GOMAXPROCS=4 make fuzz
python3 scripts/stress.py --home  # дополнительно измерить свой домашний каталог
```

Go-код использует только пакеты из списка ТЗ и собственные internal-пакеты.
В тестовых файлах дополнительно нужен стандартный `testing`. Сквозной Python-аудит
запускает эталонный `ls` вне программы и сравнивает результаты.

CI повторяет проверки в Linux на Go 1.25/1.27 и в macOS на Go 1.27.
Карта требований и границ проверки: [docs/AUDIT.md](docs/AUDIT.md).
Объяснение устройства для изучения: [docs/WALKTHROUGH.md](docs/WALKTHROUGH.md).
